[01]  Why this seriesThe problem

Why the answer depends on the situation

Consider a common question: what is the best way to get the contents out of a few thousand PDF contracts?

There is no single answer. Small scripts, classic OCR, cloud document services, specialist vendors, open models and the big general models like Gemini, GPT and Claude can all do it. Each is the right choice in some situations. The choice depends on factors such as:

How many documents?Digital or scanned?How long?Lots of tables?Charts and diagrams?How accurate?Budget?Where can the data go?What happens next?

The options also change every few months: an approach that was too expensive last year may now be the cheapest adequate option. Each session takes one task and sets out the current options, how they work, what they cost, and which to try first in common situations.

[02]  The ideaThe Pareto frontier

The Pareto frontier

Plot every option

Each dot is one way of doing the task. Up means better results on a fair test. Right means more expensive per unit of work.

Draw the frontier

An option is on the frontier if nothing else is both better and cheaper. Only these options merit detailed evaluation.

Exclude dominated options

Every option below the line is beaten on both quality and cost by an option on it. This is usually most of the market.

Apply client constraints

Constraints such as "must run in our Azure tenant" remove options. This moves the frontier and may change the best choice.

Illustrative data. Real charts are in each session.

[05]  Ground rulesHow to read these sessions
  1. Results come from published benchmarks.We do not run our own tests. We report public results, who produced them, and any likely bias.
  2. Every number has a source and a date.Prices and scores change quickly. Each session is a snapshot from the date shown on it.
  3. Benchmarks are combined only when comparable.Scores are blended only when the benchmarks measure the same thing. Each chart shows how many benchmarks back each point.
  4. Default picks indicate what to test first.Each default pick identifies the option to test first on the client's own documents. It does not replace that test.
